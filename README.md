# Nomus AI — достоинство труда, подтверждённое законом

*Nomus — dignity (узб., тадж.; каз. «намыс»).*

Safety-aware сервис, который помогает иностранным трудовым мигрантам в Казахстане
понять свои права **со ссылкой на конкретную статью закона**, получить безопасный план
действий с учётом правового статуса и готовое заявление в госинспекцию труда.
Доступен как **Telegram-бот** и как **веб-сайт** с тем же RAG-ядром.

> ℹ️ Информационно-справочный сервис. Не юридическая консультация и не адвокатская
> деятельность.

## Проблема

Сотни тысяч трудовых мигрантов в РК находятся вне правовой защиты. Обычные LLM-чаты
галлюцинируют в юридических запросах в 58–88% случаев (Stanford) — для мигранта цена
ошибки — депортация. Nomus AI отвечает **только** на основании извлечённых статей НПА РК,
проверяет каждую цитату и честно отказывается, если нормы не нашёл.

## Ключевые особенности

- **Grounded RAG**: гибридный поиск (bge-m3 dense+sparse, Qdrant, RRF) → reranker
  (bge-reranker-v2-m3) → GPT-4o со строгим JSON. Чанкинг по структуре закона
  (статья/пункт), в LLM подаётся статья целиком (parent-document retrieval).
- **Validator цитат**: каждая статья из ответа обязана присутствовать в извлечённом
  контексте, иначе ответ блокируется. Ноль выдуманных статей — блокирующий критерий.
- **Развилка ЕАЭС**: гражданин Кыргызстана и гражданин Узбекистана получают **разные**
  ответы на один вопрос (ст. 97 Договора о ЕАЭС vs разрешение на работу).
- **Safety-режим**: при отсутствии документов бот сначала направляет в НПО/консульство
  и предупреждает о рисках обращения в госорганы.
- **Red-flag детектор** принудительного труда (изъятие паспорта, ограничение свободы,
  долговая кабала) → приоритетное сообщение с горячей линией **116 16**.
- **Abstention**: нет релевантной нормы — честный отказ + контакты живой помощи.
  Запрещено отвечать из общих знаний модели.
- **Документ**: заявление в госинспекцию труда о невыплате зарплаты — текст + `.docx`,
  со ссылками на нарушенные статьи из ответа.
- **Приватность**: текст обращений не хранится (только хеш), поля заявления живут
  только в памяти сессии, `/delete` удаляет всё.

## Архитектура

```
Telegram (aiogram 3) ─┐
                      ├→ Orchestrator:
Веб-сайт (FastAPI) ───┘   Profiler → Red-flag → Query Rewriter → Hybrid Retrieval (Qdrant)
                          → Reranker → Generator (GPT-4o, strict JSON) → Citation Validator
                 │                                      │
              [SQLite]                          [корпус НПА РК: ТК, КоАП,
           сессии, метрики                   Закон о миграции, Договор о ЕАЭС]
```

Оба канала используют один и тот же оркестратор, поэтому правила безопасности
(abstention, валидация цитат, red-flag, safety-режим) действуют одинаково.

## Быстрый старт

```bash
cp .env.example .env          # заполнить TELEGRAM_BOT_TOKEN и OPENAI_API_KEY

# Вариант A: docker
docker compose up -d qdrant
pip install -r requirements.txt

# 1. Корпус: скачать (или сохранить вручную в data/raw/, см. nomus/ingest/sources.py)
python -m nomus.ingest.download
# 2. Индексация одной командой
python -m nomus.ingest
# 3. Запуск: бот и/или сайт
python -m nomus.bot.main    # Telegram-бот
python -m nomus.api.main    # сайт + API на http://localhost:8000

# Всё сразу: docker compose up
```

## Веб-часть

Сайт — лендинг с живым демо-чатом и кнопкой перехода в Telegram. Статика лежит
в [nomus/web/](nomus/web/) и отдаётся тем же FastAPI, сборщик не нужен.

| Эндпоинт | Назначение |
|---|---|
| `GET /` | лендинг с демо-чатом |
| `POST /api/ask` | вопрос + профиль → ответ со статьями и источниками |
| `POST /api/claim` | поля заявления → файл `.docx` (ничего не сохраняется) |
| `GET /api/contacts` | справочник контактов помощи |
| `GET /api/health` | статус и ссылка на бота |
| `GET /docs` | интерактивная документация OpenAPI |

Ссылка на бота задаётся переменной `BOT_USERNAME` и подставляется на страницу
из `/api/health` — менять её в HTML не нужно. Демо-чат ограничен
`RATE_LIMIT_PER_HOUR` запросами с одного IP, чтобы публичная демка не тратила
бюджет OpenAI без предела.

Проверка живого сервера: `python tests/test_api.py [base_url]`

### Публикация через cloudflared

```bash
# 1. В .env обязательно: TRUSTED_PROXY=true
python -m nomus.api.main
cloudflared tunnel --url http://localhost:8000
```

`TRUSTED_PROXY=true` включает чтение `CF-Connecting-IP` / `X-Forwarded-For`.
Без него за туннелем все посетители выглядят как `127.0.0.1` и делят один
счётчик rate limit на всех. Включать флаг **только** когда сервис
действительно стоит за прокси: при прямом доступе клиент подделает заголовок
и обойдёт лимит.

Проверено на быстром туннеле `trycloudflare.com`: лендинг, статика, все
эндпоинты и скачивание `.docx` работают, лимиты считаются раздельно по
посетителям. Для демо на публике стоит также сузить `CORS_ORIGINS` до своего
домена.

## Оценка качества

```bash
python -m eval.run_eval          # citation accuracy, abstention rate, red-flag recall
python -m eval.run_eval --ragas  # + faithfulness, context precision/recall, relevancy
```

Целевые пороги: Faithfulness ≥ 0.85, Citation Accuracy = 1.00, Abstention ≥ 0.90.

## Структура

```
nomus/
  bot/        # aiogram: FSM профилирования, рендер, заявление
  pipeline/   # rewriter, retriever, reranker, generator, validator, red-flag
  ingest/     # парсер adilet.zan.kz, чанкинг по статьям, индексация в Qdrant
  docgen.py   # заявление .docx
  db.py       # SQLite: сессии + обезличенные логи
eval/         # тестовый датасет + RAGAS
```
