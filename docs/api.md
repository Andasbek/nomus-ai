# Веб-API и сайт

FastAPI-приложение отдаёт и JSON-API, и статику лендинга. Точка входа —
[nomus/api/main.py](../nomus/api/main.py), запуск: `python -m nomus.api.main`.

Интерактивная документация доступна на `/docs` (Swagger UI), схема OpenAPI — на
`/openapi.json`.

> Исходное ТЗ выносило веб-сайт за границы MVP («только Telegram»). Канал был
> добавлен по отдельному запросу и переиспользует то же ядро, поэтому правила
> безопасности в нём не могут разойтись с ботом.

## Эндпоинты

### `POST /api/ask`

Основной запрос: вопрос и профиль пользователя.

```json
{
  "question": "Мне не платят зарплату 3 месяца, паспорт забрал работодатель",
  "citizenship": "NON_EAEU",
  "risk": "UNDOCUMENTED"
}
```

| Поле | Тип | Обязательно | Значения |
|---|---|---|---|
| `question` | строка, 3–1000 символов | да | — |
| `citizenship` | перечисление | нет | `EAEU`, `NON_EAEU`, `UNKNOWN` |
| `risk` | перечисление | нет | `DOCUMENTED`, `UNDOCUMENTED`, `UNKNOWN` |

Ответ:

```json
{
  "kind": "answer",
  "summary": "Работодатель не выплачивает зарплату и удерживает паспорт…",
  "rights": [
    {
      "statement": "Работодатель обязан выплачивать зарплату не реже раза в месяц",
      "article": "113",
      "doc_short": "ТК РК"
    }
  ],
  "risk_warning": "Обращение в госорганы может повлечь проверку статуса…",
  "action_plan": [
    {"step": 1, "action": "Обратитесь в НПО или консульство", "why": "…"}
  ],
  "contacts": ["1414", "116 16"],
  "red_flag": true,
  "red_flag_triggers": ["изъятие документов"],
  "offer_document": "labor_inspection_claim",
  "abstain_reason": null,
  "sources": [
    {
      "doc_short": "ТК РК",
      "article_num": "113",
      "article_title": "Порядок и сроки выплаты заработной платы",
      "url": "https://adilet.zan.kz/rus/docs/K1500000414#z113",
      "score": 0.943
    }
  ],
  "latency_ms": 6670,
  "disclaimer": "Это информационно-справочный сервис…"
}
```

**Поле `kind` определяет, как отображать ответ:**

| Значение | Смысл | Что показывать |
|---|---|---|
| `answer` | норма найдена, цитаты проверены | `summary`, `rights`, `action_plan` |
| `abstain` | ответа нет по правилам безопасности | `abstain_reason` и контакты помощи |
| `error` | внутренний сбой | сообщение об ошибке и телефоны |

Клиент **обязан** обрабатывать все три значения. Показать пустой экран при
`abstain` — значит потерять смысл механизма отказа.

**`red_flag` не зависит от `kind`.** Признаки принуждения выдаются даже при
отказе и при ошибке, потому что вычисляются до обращения к внешним сервисам.
Этот блок следует показывать **до** основного ответа.

**`sources`** содержит фактически найденные нормы с оценкой релевантности и
ссылками на adilet — это доказательная база ответа, её стоит показывать
пользователю.

Коды ошибок: `422` — некорректный ввод (например, слишком короткий вопрос),
`429` — превышен лимит запросов.

### `POST /api/claim`

Формирует заявление в госинспекцию труда и отдаёт файл `.docx`.

```json
{
  "full_name": "Иванов Иван Иванович",
  "citizenship": "Узбекистан",
  "employer": "ТОО Ромашка",
  "work_period": "январь–март 2026",
  "debt_amount": "450000",
  "contact": "+7 700 000 00 00",
  "violated_articles": ["ст. 113 ТК РК (сроки выплаты зарплаты)"]
}
```

Ответ — бинарный файл с заголовком `Content-Disposition: attachment`.

**Персональные данные не сохраняются.** Поля используются только для рендеринга
документа и не попадают ни в базу, ни в логи. Массив `violated_articles`
заполняется на клиенте из предыдущего ответа `/api/ask` — так в заявление
попадают статьи, подтверждённые поиском.

### `GET /api/contacts`

Справочник контактов помощи: горячие линии, госорганы, НПО, консульства.
Возвращает список объектов с полями `name`, `value`, `purpose` и ссылку на
бота.

### `GET /api/health`

```json
{"status": "ok", "bot_url": "https://t.me/nomus_law_bot"}
```

Используется и для мониторинга, и фронтендом: ссылка на Telegram-бота
подставляется на страницу отсюда, а не жёстко прописана в HTML. Чтобы сменить
бота, достаточно поменять `BOT_USERNAME` в `.env`.

## Ограничение частоты запросов

По умолчанию 30 запросов в час с одного IP (`RATE_LIMIT_PER_HOUR`). Счётчик
хранится в памяти процесса.

За обратным прокси необходимо включить `TRUSTED_PROXY=true`, иначе все
посетители будут выглядеть как один клиент и разделят общий лимит. Подробности
и объяснение, почему флаг не включён по умолчанию, — в
[Развёртывании](deployment.md).

Ограничение существует не ради нагрузки, а ради бюджета: каждый запрос
оплачивается в OpenAI.

## Фронтенд

Статика лежит в [nomus/web/](../nomus/web/) и отдаётся тем же сервисом. Сборщик
не используется — три файла без зависимостей и внешних CDN.

| Файл | Содержание |
|---|---|
| `index.html` | разметка лендинга |
| `styles.css` | оформление, тёмная тема |
| `app.js` | обращения к API и отрисовка ответов |

Страница состоит из разделов: обещание продукта и кнопка перехода в Telegram,
объяснение отличий от обычного чат-бота, живой демо-чат, справочник контактов,
призыв перейти в бота, дисклеймер в подвале.

### Демо-чат

Пользователь выбирает гражданство и статус документов, описывает ситуацию.
Ответ отображается блоками: красный блок red-flag с телефоном 116 16, суть
ситуации, права со ссылками на статьи, жёлтый блок предупреждения о рисках,
план действий, контакты и чипы найденных норм со ссылками на adilet.

Если пайплайн предложил документ, прямо в чате разворачивается форма заявления
со скачиванием `.docx`.

Весь текст, приходящий с сервера, экранируется перед вставкой в DOM.

### Ссылки на бота

Кнопка перехода в Telegram присутствует в четырёх местах: шапка, первый экран,
блок призыва и подвал. Все они получают адрес из `/api/health`.

## Интеграция: чек-лист

Если вы подключаете API к своему интерфейсу, воспроизведите правила
безопасности:

1. Обрабатывайте все три значения `kind`, не только `answer`.
2. Показывайте `red_flag` **до** основного ответа.
3. Показывайте `risk_warning`, если поле заполнено.
4. Не скрывайте `sources` — на них держится доверие к ответу.
5. Выводите `disclaimer` рядом с ответом.
6. Не сохраняйте текст вопросов и поля заявления.

Эти требования не косметические: они прямо следуют из требований безопасности
ТЗ (FR-20, FR-23, FR-24, SEC-01, SEC-02).
