# Архитектура

## Общая схема

```
Telegram (aiogram 3) ─┐
                      ├──→  Оркестратор  ──→  ответ
Веб-сайт (FastAPI) ───┘     nomus/pipeline/orchestrator.py

Внутри оркестратора:

  профиль пользователя
        │
        ▼
  1. Red-flag детектор      ключевые слова + LLM-классификатор
        │
        ▼
  2. Query Rewriter         разговорный текст → юридический запрос
        │
        ▼
  3. Retrieval              Qdrant: dense + sparse, RRF, фильтр active
        │
        ▼
  4. Rerank                 bge-reranker-v2-m3, порог 0.35
        │
        ▼
  5. Generate               GPT-4o, temperature=0, строгий JSON
        │
        ▼
  6. Validate               каждая статья обязана быть в контексте
        │
        ▼
  ответ  |  отказ  |  ошибка

Хранилища:
  Qdrant   — 1817 векторизованных фрагментов НПА
  SQLite   — сессии пользователей и обезличенные метрики
  OpenAI   — генерация (внешний сервис)
```

## Почему именно так

**Ядро отделено от каналов.** Бот и сайт не содержат логики ответа — они
собирают профиль, вызывают `process_query()` и отрисовывают результат. Это не
стилистическое решение: если бы правила безопасности жили в обработчиках, при
добавлении второго канала они бы разъехались, и веб мог бы начать отвечать
там, где бот отказывается.

**Тонкий собственный пайплайн вместо фреймворка.** Каждый шаг — обычная
функция, которую видно целиком. При отладке качества ответов важно понимать,
что именно ушло в модель; фреймворк с неявными цепочками это скрывает.

**Retrieval отделён от reranking.** Первый этап широкий и дешёвый (20
кандидатов), второй точный и дорогой (5 лучших). Обратный порядок был бы
неподъёмным: cross-encoder не запустишь по всему корпусу.

**Валидация цитат вынесена в отдельный шаг после генерации.** Промпт может
просить модель не выдумывать статьи, но проверка исполнения этого требования не
должна зависеть от самой модели. Валидатор сверяет ответ с фактически
найденными фрагментами программно.

## Компоненты

### RAG-ядро (`nomus/pipeline/`)

| Модуль | Ответственность |
|---|---|
| `orchestrator.py` | последовательность шагов, обработка отказов и ошибок |
| `redflag.py` | признаки принудительного труда |
| `rewriter.py` | переформулировка запроса с учётом правового режима |
| `retriever.py` | гибридный поиск в Qdrant, квота для Договора о ЕАЭС |
| `reranker.py` | cross-encoder, пересчёт релевантности |
| `generator.py` | системный промпт и вызов GPT-4o |
| `validator.py` | сверка цитат с контекстом |
| `embeddings.py` | обёртка над bge-m3 (dense + sparse) |
| `device.py` | автовыбор GPU/CPU и режима fp16 |

Подробности каждого шага — в [Пайплайн ответа](pipeline.md).

### Каналы

**Telegram-бот** (`nomus/bot/`) — aiogram 3 с конечным автоматом: дисклеймер →
гражданство → наличие договора → наличие регистрации → приём вопросов. Профиль
хранится в SQLite и не запрашивается повторно. См. [Telegram-бот](bot.md).

**Веб-API и сайт** (`nomus/api/`, `nomus/web/`) — FastAPI отдаёт и JSON-API, и
статику лендинга. Профиль передаётся в каждом запросе, серверных сессий нет.
См. [Веб-API](api.md).

### Подготовка данных (`nomus/ingest/`)

Парсер разбирает сохранённые страницы adilet.zan.kz по иерархии
глава → статья → пункт, отсеивает утратившие силу нормы и загружает векторы в
Qdrant одной командой. См. [Корпус НПА](corpus.md).

## Модель данных

### Профиль пользователя

Две независимые оси, обе влияют на ответ (§2 ТЗ):

| Ось | Значения | На что влияет |
|---|---|---|
| Гражданство | `EAEU`, `NON_EAEU`, `UNKNOWN` | какая норма применима |
| Документы | `DOCUMENTED`, `UNDOCUMENTED`, `UNKNOWN` | насколько безопасен совет |

`UNKNOWN` в оси документов трактуется консервативно — как `UNDOCUMENTED`. Это
реализовано свойством `UserProfile.effective_risk` в
[schemas.py](../nomus/schemas.py), а не разрозненными проверками в коде: если бы
каждый вызывающий решал сам, рано или поздно кто-то забыл бы, и пользователь без
профиля получил бы небезопасный совет.

### Фрагмент корпуса

Минимальная единица — пункт статьи, но в модель подаётся статья целиком
(parent-document retrieval): пункт хорошо ищется, а понимается только в
контексте всей статьи. Полная схема — в [Корпус НПА](corpus.md).

### Ответ модели

Модель обязана вернуть строгий JSON: краткая суть, список прав с номерами
статей, предупреждение о рисках, пошаговый план, контакты, признак red-flag и
предложение документа. Свободный текст не принимается — иначе цитаты
невозможно проверить программно.

## Потоки данных и приватность

Что сохраняется:

- **SQLite `sessions`** — профиль пользователя Telegram и факт принятия
  дисклеймера.
- **SQLite `queries`** — SHA-256 хеш вопроса, идентификаторы найденных
  фрагментов, уверенность, признаки red-flag и отказа, задержка.

Что **не** сохраняется:

- текст обращений (только хеш);
- персональные данные из заявления — они живут в памяти сессии и стираются
  после генерации файла;
- паспортные данные не запрашиваются вовсе.

Подробнее — [Безопасность и приватность](safety.md).

## Внешние зависимости

| Зависимость | Роль | Что будет при отказе |
|---|---|---|
| OpenAI API | генерация, rewriter, LLM-детектор | ответ об ошибке с контактами помощи; red-flag по ключевым словам продолжает работать |
| Qdrant | векторный поиск | тот же путь деградации |
| HuggingFace Hub | загрузка моделей при первом запуске | после кэширования не нужен |
| adilet.zan.kz | источник НПА | нужен только при обновлении корпуса |

Оркестратор оборачивает весь путь в `try/except` и в худшем случае возвращает
`kind="error"` — сервис отвечает сообщением об ошибке и телефонами живой помощи
(требование NFR-06). Молчания или падения пользователь не увидит.

## Производительность

Замеры на RTX 3070, корпус 1817 фрагментов:

| Этап | Время |
|---|---|
| Rewriter (GPT-4o) | ~1 с |
| Retrieval (Qdrant + bge-m3) | ~0,3 с |
| Rerank (20 пар, GPU) | ~0,15 с |
| Генерация (GPT-4o) | 2–5 с |
| **Итого тёплый запрос** | **1,3–7,2 с** |

Требование NFR-01 (p95 ≤ 12 с) выполняется. Первый запрос после старта занимал
бы около 40 секунд из-за ленивой загрузки моделей, поэтому и бот, и API
прогревают модели до приёма запросов — см. [Развёртывание](deployment.md).

Reranker на CPU работает в разы медленнее; автовыбор устройства описан в
[Пайплайн ответа](pipeline.md).
