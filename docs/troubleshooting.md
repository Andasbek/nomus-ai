# Решение проблем

Ниже — ошибки, с которыми проект реально столкнулся при запуске, и их причины.

## Reranker падает с ошибкой prepare_for_model

```
AttributeError: XLMRobertaTokenizer has no attribute prepare_for_model
```

**Причина.** В `transformers` 5.x у медленных токенизаторов удалён метод
`prepare_for_model`, а обёртка `FlagReranker` из библиотеки `FlagEmbedding` его
вызывает.

**Решение.** В проекте reranker уже переписан на прямое использование
`transformers`: `AutoModelForSequenceClassification` плюс сигмоида — это
официальный способ работы с `bge-reranker-v2-m3`. Если вы вернули обёртку
`FlagEmbedding`, либо откатитесь на `transformers` 4.x, либо используйте
текущую реализацию в [reranker.py](../nomus/pipeline/reranker.py).

**Как это выглядело со стороны пользователя.** Пайплайн возвращал `kind="error"`
с сообщением об ошибке и телефонами помощи, но red-flag по ключевым словам
продолжал срабатывать. Это штатное поведение деградации (NFR-06), а не
дополнительный сбой.

## torch не видит GPU

`torch.cuda.is_available()` возвращает `False` при наличии карты.

**Причина.** Установлена сборка torch для CPU (в версии виден суффикс `+cpu`).

**Ловушка.** Команда `pip install --index-url ... torch` может ничего не
сделать: если номер версии совпадает с уже установленным, pip считает
требование выполненным и оставляет CPU-сборку на месте.

**Решение.** Указывайте версию явно, вместе с суффиксом CUDA:

```bash
pip index versions torch --index-url https://download.pytorch.org/whl/cu130
pip install --index-url https://download.pytorch.org/whl/cu130 "torch==2.13.0+cu130"
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Вторая ловушка: индексы разных версий CUDA содержат разные наборы версий torch.
Если в `cu128` нужной версии нет, она может быть в `cu130`. Сверяйтесь с
командой `pip index versions`.

## Не скачиваются НПА с adilet.zan.kz

```
[SSL: CERTIFICATE_VERIFY_FAILED] unable to get local issuer certificate
```

**Причина.** Набор корневых сертификатов, которым пользуется `httpx`, не
содержит промежуточный сертификат сайта.

**Решение.** Скачайте через `curl` — на Windows он проверяет сертификаты через
системное хранилище и обычно проходит:

```bash
curl -sSL -A "Mozilla/5.0" -o data/raw/tk_rk.html https://adilet.zan.kz/rus/docs/K1500000414
curl -sSL -A "Mozilla/5.0" -o data/raw/migration_law.html https://adilet.zan.kz/rus/docs/Z1100000477
curl -sSL -A "Mozilla/5.0" -o data/raw/koap_rk.html https://adilet.zan.kz/rus/docs/K1400000235
curl -sSL -A "Mozilla/5.0" -o data/raw/eaeu_treaty_full.html https://adilet.zan.kz/rus/docs/Z1400000240
```

Запасной вариант — сохранить страницы вручную из браузера в `data/raw/` под
именами из [sources.py](../nomus/ingest/sources.py).

**Отключать проверку сертификатов не следует.** Корпус определяет содержание
правовых ответов; подмена источника здесь — не теоретический риск.

## Бот отвечает отказом на очевидный вопрос

Проверяйте по порядку.

**Корпус проиндексирован?**

```bash
curl http://localhost:6333/collections/nomus_kz_legal_v1
```

Число точек должно быть около 1817. Ноль или отсутствие коллекции означает, что
`python -m nomus.ingest` не выполнялся.

**Нужная норма вообще есть в корпусе?**

```bash
python -c "
import json
c = json.load(open('data/chunks/chunks.json', encoding='utf-8'))
print([x['chunk_id'] for x in c if x['article_num'] == '113' and x['doc_short'] == 'ТК РК'])
"
```

**Не слишком ли высок порог?** Понизьте `RELEVANCE_THRESHOLD` и посмотрите
оценки в поле `sources` ответа API — там видно, насколько близко фрагменты
подошли к порогу.

**Вопрос действительно вне области?** Семейное, уголовное, налоговое и жилищное
право находятся за границами MVP, и отказ там — правильное поведение.

## Развилка ЕАЭС не срабатывает

Признак: гражданин страны ЕАЭС получает отказ или ответ по общим миграционным
нормам вместо статьи 97 Договора о ЕАЭС.

**Причина.** Договор о ЕАЭС занимает 33 фрагмента против более чем 2200 у
остальных документов и тонет в общей выдаче.

**Решение** уже встроено: для профиля `EAEU` выполняется дополнительный поиск,
ограниченный Договором о ЕАЭС, а переформулировка запроса добавляет термины
правового режима. Если проблема вернулась, проверьте:

1. Договор проиндексирован — в `chunks.json` должны быть статьи 96–98.
2. Профиль действительно `EAEU` — в боте это Кыргызстан, на сайте выбор в
   выпадающем списке.
3. Оба механизма на месте: квота в [retriever.py](../nomus/pipeline/retriever.py)
   и подсказка режима в [rewriter.py](../nomus/pipeline/rewriter.py).

## Первый запрос идёт 40 секунд

**Причина.** Ленивая загрузка моделей: bge-m3 и reranker подгружаются при
первом обращении.

**Решение.** Прогрев уже выполняется при старте бота и API — дождитесь строк
`Модели готовы` и `Application startup complete` перед тем, как принимать
пользователей. Если прогрев отключён, первый пользователь оплатит загрузку
своим ожиданием.

## Все посетители сайта делят один лимит

Признак: за туннелем посторонние люди получают «слишком много запросов», хотя
сами ничего не отправляли.

**Причина.** Без `TRUSTED_PROXY=true` сервис видит адрес прокси, а не
посетителя, и считает всех одним клиентом.

**Решение.** Включите `TRUSTED_PROXY=true` — но **только** если сервис
действительно стоит за прокси. При прямом доступе этот режим позволил бы
обойти лимит подделкой заголовка. Подробнее — в
[Развёртывании](deployment.md).

## Ошибки кодировки в консоли Windows

Русский текст в выводе выглядит как `РњРѕРґРµР»Рё`.

**Причина.** Консоль интерпретирует UTF-8 как однобайтовую кодировку. На работу
сервиса это не влияет — искажён только вывод.

**Решение.** `chcp 65001` перед запуском либо просмотр логов через файл.

## Парсер выдал мало фрагментов

Признак: `[parse] ...: 3 чанков` вместо сотен.

**Причина.** Структура сохранённой страницы отличается от ожидаемой — например,
сохранена версия для печати или страница-оглавление вместо текста документа.

**Решение.** Убедитесь, что в файле присутствуют строки вида `Статья 113.
Название`. Парсер опирается на этот формат; для другой разметки потребуется
правка регулярных выражений в [parser.py](../nomus/ingest/parser.py).

## Qdrant не отвечает

```bash
docker ps -a --filter name=qdrant
docker compose start qdrant
curl http://localhost:6333/healthz
```

Если контейнер остановлен, индекс не потерян — данные лежат в каталоге
`./.qdrant` и переживают перезапуск.

## Git отказывается делать коммит

```
Author identity unknown
```

**Причина.** Не настроены имя и почта.

**Решение.** Настройте их **локально** для репозитория, чтобы не менять
глобальные настройки системы:

```bash
git config user.name "Ваше имя"
git config user.email "почта@example.com"
```

## Если ключ попал в репозиторий

Удаления файла недостаточно — история коммитов остаётся доступной.

1. **Немедленно отзовите ключ** у провайдера: OpenAI — в панели ключей,
   Telegram — командой `/revoke` у BotFather.
2. Выпустите новый и запишите в `.env`.
3. Только после этого занимайтесь очисткой истории.

Порядок важен: пока старый ключ действителен, очистка истории не защищает.
