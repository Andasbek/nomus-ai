# Развёртывание

## Через Docker Compose

```bash
docker compose up -d
```

Поднимаются три сервиса:

| Сервис | Назначение | Порт |
|---|---|---|
| `qdrant` | векторная база | 6333 |
| `bot` | Telegram-бот | — |
| `api` | сайт и веб-API | 8000 |

Постоянные данные: индекс в `./.qdrant`, база сессий в `./data`, веса моделей в
томе `hf_cache`. Пересборка образа не приводит к повторной загрузке моделей.

Корпус нужно проиндексировать один раз — `python -m nomus.ingest` на хосте или
внутри контейнера.

## Публикация через cloudflared

Быстрый туннель для демонстрации:

```bash
# в .env обязательно: TRUSTED_PROXY=true
python -m nomus.api.main
cloudflared tunnel --url http://localhost:8000
```

Cloudflared выдаст адрес вида `https://<случайное-имя>.trycloudflare.com`.

### Зачем нужен TRUSTED_PROXY

Cloudflared обращается к сервису с локального адреса, поэтому без специальной
обработки **все посетители выглядят как один клиент** `127.0.0.1` и делят общий
лимит запросов: тридцать обращений на весь интернет в час, после чего
тридцать первый посетитель получает отказ, ничего не сделав.

Флаг `TRUSTED_PROXY=true` включает чтение заголовка `CF-Connecting-IP` (его
Cloudflare перезаписывает сам, поэтому он надёжнее `X-Forwarded-For`) и режим
`proxy_headers` в uvicorn, чтобы схема URL определялась как https.

**Флаг не включён по умолчанию намеренно.** При прямом доступе к сервису
доверие к заголовкам позволило бы любому клиенту подделать `X-Forwarded-For` и
обойти ограничение частоты. Включайте его только там, где перед сервисом
действительно стоит прокси.

Проверено на быстром туннеле: лендинг, статика, все эндпоинты и скачивание
документа работают, лимиты считаются раздельно по посетителям.

### Ограничения быстрого туннеля

- **Адрес меняется** при каждом перезапуске. Если ссылку нужно раздать заранее,
  создайте именованный туннель со своим доменом:
  `cloudflared tunnel create` и `cloudflared tunnel route dns`.
- **Тайм-аут около 100 секунд.** Тёплые запросы занимают 1–7 секунд и проходят
  свободно, но первый запрос после старта требует загрузки моделей. Дождитесь
  строки `Application startup complete`, прежде чем открывать ссылку зрителям.

Telegram-бот от туннеля не зависит: он работает через опрос серверов Telegram и
не требует входящих подключений.

## Прогрев моделей

И бот, и API загружают модели поиска и переоценки до приёма запросов. Без этого
первое обращение занимало бы около 40 секунд.

Требование NFR-04 прямо говорит о заранее прогретом экземпляре — на
демонстрации холодный старт выглядит как зависший сервис.

Если прогрев не удался, процесс всё равно поднимается и отвечает сообщением об
ошибке с телефонами помощи, а не падает.

## Контрольный список для публичного запуска

**Безопасность**

- [ ] `.env` не в репозитории, ключи не в истории коммитов
- [ ] `CORS_ORIGINS` сужен до вашего домена вместо `*`
- [ ] `TRUSTED_PROXY` соответствует схеме развёртывания
- [ ] `RATE_LIMIT_PER_HOUR` согласован с бюджетом OpenAI

**Данные**

- [ ] корпус проиндексирован, коллекция содержит ожидаемое число точек
- [ ] даты редакций НПА сверены с первоисточником
- [ ] контакты и телефоны перепроверены

**Работоспособность**

- [ ] `python tests/test_api.py <адрес>` проходит полностью
- [ ] прогрев завершён до открытия доступа
- [ ] проверены сценарии red-flag, развилки ЕАЭС и отказа

## Ограничения текущей реализации

Проект собран как MVP для демонстрации. Что стоит изменить при переходе к
постоянной эксплуатации:

**Лимит запросов хранится в памяти процесса.** При нескольких экземплярах
сервиса счётчики не будут общими, а перезапуск обнуляет их. Нужен Redis или
аналог.

**SQLite подходит для одного экземпляра.** При горизонтальном масштабировании
потребуется PostgreSQL — схема простая, миграция несложная.

**Состояние диалога бота в памяти.** После перезапуска незавершённый сбор полей
заявления придётся начать заново. Профиль при этом сохраняется, поскольку лежит
в базе. Для устойчивости — хранилище состояния на Redis.

**Нет мониторинга и оповещений.** Есть `/api/health` и статистика в таблице
`queries`, но внешнего наблюдения не настроено.

**Ключ OpenAI без ограничения расходов.** Стоит выставить лимит на стороне
провайдера — ограничение частоты в сервисе защищает лишь от простого перебора.

## Требования к ресурсам

| Ресурс | Минимум | Комментарий |
|---|---|---|
| Оперативная память | 8 ГБ | обе модели загружаются в память |
| Диск | 6 ГБ | веса моделей и индекс |
| GPU | не обязателен | ускоряет переоценку в десятки раз |
| Сеть | стабильная | вызовы OpenAI на каждый запрос |

На CPU сервис работает, но переоценка релевантности занимает секунды вместо
долей секунды. ТЗ отдельно отмечало это как риск и предлагало при необходимости
уменьшить число кандидатов.
