# Техническое задание: «Nomus AI» — safety-aware навигатор трудовых прав для мигрантов в РК

**Версия:** 1.0 (MVP для хакатона)
**Формат:** Telegram-бот + RAG по законодательству РК
**Срок реализации:** 48 часов
**Дата:** август 2026

## 1. Паспорт проекта

| Параметр | Значение |
|---|---|
| Название | **Nomus AI** (номус / нoмус — «достоинство, честь» в узбекском и таджикском; намыс — в казахском) |
| Репозиторий | github.com/Andasbek/nomus-ai |
| Тип продукта | Telegram-бот с RAG-ядром по НПА РК |
| Целевая аудитория | Иностранные трудовые мигранты в РК (Узбекистан, Таджикистан, Кыргызстан) |
| Позиционирование | Информационно-справочный сервис по правовой информации. **Не** юридическая консультация, **не** адвокатская деятельность |
| Ключевой дифференциатор | Grounded-ответы с цитатой статьи + развилка ЕАЭС + safety-режим + генерация документа |
| Языки MVP | Русский (обязательно), узбекский (желательно) |

### 1.0. Нейминг и позиционирование бренда

**Почему имя работает.** «Номус» — общее слово для узбекского, таджикского и казахского языков со значением «достоинство, честь, совесть». Целевая аудитория понимает его без перевода — в отличие от англоязычного `LawBot`. Смысловая рамка продукта: *«ваш труд имеет достоинство»* — это точнее, чем «защита», потому что продукт не защищает вместо человека, а возвращает ему субъектность.

**Слоган для питча:** «Nomus AI — достоинство труда, подтверждённое законом».

**Что учесть.** У корня «намус/nomus» в регионе есть второе, более узкое значение, связанное с честью семьи и женской репутацией; в международной правозащитной среде слово ассоциируется с honour-based violence. Это не блокер, но задаёт два правила:

| Правило | Как исполнять |
|---|---|
| N-01 | В англоязычных материалах для грантодателей (IOM, ILO, ЕС) **всегда** давать глоссу: *Nomus — dignity* — и не оставлять слово без перевода |
| N-02 | В визуале и копирайте не использовать гендерные образы и семейную тематику; только трудовой контекст |
| N-03 | Домены и хендлы бронировать связкой: `nomus.kz`, `@nomus_ai_bot`, репозиторий уже занят |

### 1.1. Цель MVP

Дать мигранту за 2–3 минуты диалога в Telegram:
1. понятное объяснение его прав со ссылкой на конкретную статью действующего НПА РК;
2. пошаговый план действий, **безопасный с учётом его правового статуса**;
3. готовый к отправке документ (заявление в госинспекцию труда);
4. контакт живой помощи при признаках принудительного труда.

### 1.2. Границы MVP (scope)

**Входит:**
- Один домен права — трудовые отношения и трудовая миграция.
- Топ-5 сценариев (см. §4).
- Русский язык интерфейса и ответов.
- Текстовый ввод.

**НЕ входит (явно фиксируем, чтобы не расползлось):**
- Семейное, уголовное, налоговое, жилищное право.
- Представительство в суде, подача документов от имени пользователя.
- Оплата, личный кабинет, авторизация.
- Автоматическая отправка обращений в госорганы.
- Мобильное приложение, веб-сайт (только Telegram).

## 2. Пользователи и риск-профили

Система **обязана** на первом шаге классифицировать пользователя по двум осям, потому что от них зависит и правовая норма, и безопасность совета.

### 2.1. Ось А — гражданство (правовая норма)

| Профиль | Кто | Правовой режим |
|---|---|---|
| `EAEU` | Кыргызстан, Россия, Армения, Беларусь | Работа без разрешения на основании трудового договора (ст. 97 Договора о ЕАЭС) |
| `NON_EAEU` | Узбекистан, Таджикистан и др. | Требуется разрешение на работу / патент, отдельные правила регистрации |

### 2.2. Ось Б — документальный статус (профиль риска)

| Профиль | Признак | Влияние на ответ |
|---|---|---|
| `DOCUMENTED` | Есть договор, регистрация, разрешение | Полный набор каналов, включая госорганы |
| `UNDOCUMENTED` | Нет договора / просрочена регистрация / изъят паспорт | **Safety-режим:** сначала НПО и консульство, явное предупреждение о рисках обращения в госорганы |
| `UNKNOWN` | Не удалось определить | Отвечаем консервативно, как для `UNDOCUMENTED` |

> **Правило безопасности №1.** При `UNDOCUMENTED` бот не выдаёт рекомендацию «обратитесь в полицию / подайте через e-Otinish» первым шагом без предупреждения о возможных последствиях для статуса пользователя.

## 3. Архитектура системы

```
Telegram User
     │
     ▼
[Telegram Bot API]  ← aiogram / python-telegram-bot
     │
     ▼
┌─────────────── Orchestrator (FastAPI / Python) ───────────────┐
│                                                               │
│  1. Profiler        → определение EAEU / статуса              │
│  2. Triage          → срочность + red-flag детектор           │
│  3. Query Rewriter  → разговорный текст → юридический запрос  │
│  4. Retriever       → BM25 + dense (гибрид)                   │
│  5. Reranker        → BGE-reranker-v2-m3                      │
│  6. Generator       → LLM + strict JSON + citations           │
│  7. Validator       → проверка цитат / abstention             │
│  8. Doc Generator   → заполнение шаблона заявления            │
│                                                               │
└───────────────────────────────────────────────────────────────┘
     │                          │                    │
     ▼                          ▼                    ▼
[Qdrant]                  [SQLite/Postgres]     [OpenAI API]
корпус НПА                 сессии, логи          GPT-4o
```

## 6. Пайплайн ответа

### 6.1. Последовательность

1. **Profiler** — берёт `citizenship_profile` и `risk_profile` из сессии.
2. **Red-flag detector** — LLM-классификатор + ключевые слова. При срабатывании ответ формируется по особому шаблону.
3. **Query Rewriter** — LLM превращает «мне не платят 3 месяца, паспорт забрали» в юридический запрос: «невыплата заработной платы, сроки выплаты, ответственность работодателя, изъятие документа, удостоверяющего личность».
4. **Retrieval** — гибридный поиск в Qdrant: dense + sparse, RRF-объединение, фильтр `status = active`. Top-20.
5. **Rerank** — bge-reranker-v2-m3, top-5. Порог релевантности `score >= 0.35`.
6. **Generate** — GPT-4o со строгим system-промптом и JSON-схемой.
7. **Validate** — проверка, что все `article_num` из ответа есть в контексте; проверка обязательных полей.
8. **Render** — сборка сообщения для Telegram + inline-кнопки.

### 6.2. Правила abstention

Бот **обязан** отказаться от содержательного ответа, если выполнено любое условие:
- после reranking ни один фрагмент не набрал `score >= 0.35`;
- Validator обнаружил цитату статьи, отсутствующей в контексте;
- вопрос вне домена трудовых отношений и миграции;
- LLM вернул `confidence = "low"`.

Текст отказа: честное «я не нашёл точной нормы» + контакты живой помощи. **Запрещено** генерировать ответ по общим знаниям модели.

### 6.3. System-промпт генератора (черновик)

```
Ты — информационно-справочный помощник по трудовым правам иностранных
работников в Республике Казахстан.

ЖЁСТКИЕ ПРАВИЛА:
1. Отвечай ИСКЛЮЧИТЕЛЬНО на основании фрагментов в блоке CONTEXT.
2. Запрещено использовать знания вне CONTEXT. Если нормы нет —
   верни confidence: "low".
3. Каждое правовое утверждение сопровождай точной ссылкой:
   номер статьи и название НПА из метаданных фрагмента.
4. Не выдумывай номера статей. Не обобщай, если норма не найдена.
5. Пиши простым языком уровня 8 класса, короткими предложениями.
   Пользователь может плохо владеть русским.
6. Ты НЕ адвокат. Не обещай исход дела. Не давай гарантий.

ПРОФИЛЬ ПОЛЬЗОВАТЕЛЯ:
- Правовой режим: {EAEU | NON_EAEU}
- Профиль риска: {DOCUMENTED | UNDOCUMENTED | UNKNOWN}

Если профиль риска UNDOCUMENTED — в план действий первым шагом ставь
обращение в НПО или консульство, и обязательно предупреди, что
обращение в государственные органы может повлечь проверку статуса.

Верни строго JSON по схеме ANSWER_SCHEMA. Без markdown-обёртки.
```

## 7. Модель данных (SQLite)

```sql
CREATE TABLE sessions (
    user_id            INTEGER PRIMARY KEY,
    citizenship_profile TEXT,      -- EAEU | NON_EAEU | UNKNOWN
    risk_profile       TEXT,       -- DOCUMENTED | UNDOCUMENTED | UNKNOWN
    lang               TEXT DEFAULT 'ru',
    disclaimer_ack     INTEGER DEFAULT 0,
    created_at         TIMESTAMP
);

CREATE TABLE queries (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id       INTEGER,
    query_hash    TEXT,            -- хеш, НЕ сырой текст
    retrieved_ids TEXT,            -- JSON-массив chunk_id
    confidence    TEXT,
    red_flag      INTEGER,
    abstained     INTEGER,
    latency_ms    INTEGER,
    created_at    TIMESTAMP
);
```

> **Приватность.** В `queries` не сохраняется сырой текст обращения и персональные данные. Для метрик достаточно хеша и служебных полей. Поля заявления (ФИО, работодатель) держатся только в оперативной памяти сессии и удаляются после генерации файла.

## 8. Безопасность, право и приватность

### 8.1. Дисклеймер (обязателен при `/start` и в подвале каждого правового ответа)

> Это информационно-справочный сервис. Я предоставляю правовую информацию со ссылками на законы РК, но **не оказываю юридическую консультацию** и не заменяю адвоката. Для решения вашего дела обратитесь к юристу или в организацию помощи мигрантам.

### 8.2. Требования соответствия

| ID | Требование |
|---|---|
| SEC-01 | Явное уведомление, что пользователь общается с ИИ (требование Закона РК «Об искусственном интеллекте» № 230-VIII, введён в действие 18.01.2026) |
| SEC-02 | Минимизация персональных данных; отказ от хранения паспортных данных (Закон РК «О персональных данных и их защите») |
| SEC-03 | Честное предупреждение, что переписка в Telegram не даёт абсолютной анонимности |
| SEC-04 | Возможность удалить свои данные командой `/delete` |
| SEC-05 | Ключи API — только в переменных окружения, не в репозитории |

### 8.3. Red-flag: признаки принудительного труда

Триггеры: изъятие документа, удостоверяющего личность; запрет покидать территорию; долговая кабала; работа без оплаты под угрозой; удержание «за жильё и еду» сверх зарплаты.

Реакция: приоритетное сообщение до основного ответа, телефон 116 16 (национальная горячая линия по борьбе с торговлей людьми, круглосуточно, бесплатно), предложение связаться с профильным НПО.

| NFR-04 | Доступность во время питча | 100% (заранее прогретый инстанс + запасной ноутбук) |
| NFR-05 | Воспроизводимость сборки | `docker compose up` поднимает всё |
| NFR-06 | Работа при отказе LLM API | Graceful degradation: сообщение об ошибке + контакты помощи |

## 10. Метрики и приёмочные критерии

### 10.1. Тестовый датасет

Собрать **40 вопросов** на основе типовых кейсов из отчётов IOM, ILO и НПО. Формат:

```json
{
  "id": "q_014",
  "question": "Не платят зарплату 3 месяца, договора нет",
  "profile": {"citizenship": "NON_EAEU", "risk": "UNDOCUMENTED"},
  "ground_truth": "Эталонный ответ",
  "expected_articles": ["113", "23"],
  "expects_red_flag": false,
  "expects_abstention": false
}
```

Распределение: 25 вопросов «в домене», 8 пограничных, 7 заведомо вне домена (проверка abstention).

### 10.2. Целевые метрики (RAGAS)

| Метрика | Порог приёмки | Комментарий |
|---|---|---|
| Faithfulness | ≥ 0.85 | Доля утверждений, подтверждённых контекстом. **Главная метрика** |
| Context Precision | ≥ 0.70 | Качество retrieval |
| Context Recall | ≥ 0.75 | Полнота извлечения |
| Answer Relevancy | ≥ 0.80 | Соответствие ответа вопросу |
| Citation Accuracy | = 1.00 | Ноль выдуманных статей. **Блокирующий критерий** |
| Abstention Rate (вне домена) | ≥ 0.90 | Отказ там, где нужно отказаться |

### 10.3. Definition of Done для MVP

- [ ] Бот отвечает на 5 демо-сценариев без ошибок 3 прогона подряд
- [ ] Ни одной выдуманной статьи на всём тест-датасете
- [ ] Faithfulness ≥ 0.85 замерена и вынесена на слайд
- [ ] Развилка ЕАЭС даёт **разные** ответы на один и тот же вопрос
- [ ] Заявление генерируется и скачивается как `.docx`
- [ ] Red-flag срабатывает на кейсе с изъятием паспорта
- [ ] Есть сравнительный слайд «наш ответ vs голый GPT» на одном вопросе

## 11. План работ на 48 часов

Команда: 3–4 человека. Роли: **D** — данные/ingest, **R** — RAG-ядро, **B** — бот/UX, **P** — питч/дизайн/eval.

### Час 0–6: фундамент

| Кто | Задача |
|---|---|
| D | Скачать ТК РК, Закон о миграции, главы КоАП. Написать парсер по статьям |
| R | Поднять Qdrant в docker, загрузить bge-m3, проверить эмбеддинги |
| B | Скелет aiogram-бота, `/start`, FSM профилирования, дисклеймер |
| P | Каркас питч-дека, начать сбор 40 тестовых вопросов |
| P | Оформить репозиторий: description, topics (`rag`, `legal-tech`, `migrant-rights`, `kazakhstan`), README с проблемой и архитектурой, лицензия |

**Контрольная точка Ч+6:** парсер выдаёт валидный JSON чанков; бот отвечает «эхо».

### Час 6–18: ядро

| Кто | Задача |
|---|---|
| D | Индексация корпуса, метаданные, отсев неактуальных норм |
| R | Гибридный retrieval + reranker + генератор с JSON-схемой |
| B | Подключение пайплайна к боту, рендер ответа, inline-кнопки |
| P | Дописать датасет, собрать справочник контактов |

**Контрольная точка Ч+18:** сквозной ответ с цитатой статьи по одному сценарию.

### Час 18–30: дифференциаторы

| Кто | Задача |
|---|---|
| R | Validator цитат, abstention, red-flag детектор |
| R/D | Логика ветвления EAEU / NON_EAEU в промпте и фильтрах |
| B | Генерация заявления `.docx`, сбор полей |
| P | Прогон RAGAS, первые метрики |

**Контрольная точка Ч+30:** все 5 демо-сценариев проходят.

### Час 30–40: качество

| Кто | Задача |
|---|---|
| Все | Итерации по метрикам: тюнинг порогов, промптов, chunk-размера |
| B | UX-полировка: эмодзи-структура, короткие сообщения, «печатает…» |
| P | Финальный прогон RAGAS, слайд с метриками, слайд «vs GPT» |

**Стоп-правило:** если faithfulness < 0.80 на Ч+36 — **не расширять корпус**, а сужать контекст и усиливать reranking.

### Час 40–48: демо

| Кто | Задача |
|---|---|
| Все | Заморозка кода. Только фикс критичных багов |
| P | Репетиция 3-минутного демо ×5, прогон 10 вопросов жюри |
| B | Запасной сценарий: записанный скринкаст на случай падения сети |

## 12. Демо-сценарий (3 минуты)

1. **0:00–0:20** — Проблема: ~14 тыс. официальных разрешений против сотен тысяч фактических мигрантов. Люди вне правовой защиты.
2. **0:20–0:40** — Почему не ChatGPT: слайд с исследованием Stanford (58–88% галлюцинаций в юридических запросах) и делом Mata v. Avianca (штраф $5 000 за выдуманные прецеденты).
3. **0:40–1:40** — Живое демо. Ввод: *«Мне не платят зарплату 3 месяца, паспорт забрал работодатель»*.
   - Бот определяет: гражданин Узбекистана → `NON_EAEU`, паспорт изъят → `UNDOCUMENTED`.
   - Выдаёт права со ссылками на статьи ТК РК.
   - Срабатывает red-flag → телефон 116 16.
   - Добавляет предупреждение о рисках обращения в госорганы.
4. **1:40–2:10** — Кнопка «Сформировать заявление» → сбор полей → скачивается `.docx`.
5. **2:10–2:30** — Тот же вопрос от гражданина Кыргызстана → **другой ответ** (режим ЕАЭС). Показ глубины домена.
6. **2:30–3:00** — Слайд метрик: faithfulness 0.8x, ноль выдуманных статей, 90% abstention вне домена. Рядом — что выдал «голый GPT» на тот же вопрос.

## 13. Риски проекта и митигация

| Риск | Вероятность | Митигация |
|---|---|---|
| Парсинг adilet.zan.kz окажется сложнее ожидаемого | Высокая | Fallback: ручное сохранение 3 документов в HTML/текст и парсинг локально. Заложить на это не более 4 часов |
| Reranker тормозит на CPU | Средняя | Уменьшить top-k до 10; при крайности — отключить reranker, компенсировать порогом |
| Не хватает времени на генерацию `.docx` | Средняя | Fallback: выдать текст заявления сообщением с кнопкой «Скопировать» |
| Падение сети на питче | Средняя | Записанный скринкаст демо + скриншоты в деке |
| Низкая faithfulness | Средняя | Сузить корпус до ТК РК, уменьшить контекст до top-3, ужесточить промпт |
| Голосовой ввод на узбекском даёт плохое качество | Высокая | Вынести в roadmap, не показывать в демо |

## 14. Roadmap после хакатона

**Q1:** мультиязычность (узбекский, таджикский, кыргызский), голосовой ввод, пайплайн автообновления НПА с отслеживанием редакций.
**Q2:** партнёрство с НПО для эскалации к живым юристам; B2B-версия для работодателей и кадровых агентств (комплаенс, снижение штрафов).
**Q3:** расширение доменов (аренда жилья, медицина, семейное право); анонимная агрегация кейсов для выявления системных нарушителей.
