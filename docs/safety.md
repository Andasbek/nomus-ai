# Безопасность, право и приватность

Аудитория продукта — люди в уязвимом положении, для которых неверный совет
означает потерю денег, задержание или депортацию. Поэтому ограничения ниже —
не формальность, а суть продукта.

## Позиционирование

Nomus AI — **информационно-справочный сервис**. Он не оказывает юридическую
консультацию, не ведёт адвокатскую деятельность, не представляет интересы
пользователя и не подаёт документы от его имени.

Дисклеймер показывается при первом запуске и сопровождает каждый правовой
ответ. В веб-версии он же приходит в поле `disclaimer` каждого ответа API.

## Три барьера против выдуманных статей

Обычная языковая модель галлюцинирует в юридических запросах в значительной
доле случаев. В продукте для мигрантов это недопустимо, поэтому выдумывание
блокируется на трёх уровнях.

**Первый: модель не имеет знаний.** Системный промпт запрещает использовать что
-либо вне переданных фрагментов закона. При отсутствии нормы модель обязана
вернуть низкую уверенность.

**Второй: программная проверка цитат.** Каждая пара «статья + документ» из
ответа сверяется с фактически найденными фрагментами. Несовпадение блокирует
ответ целиком. Проверку выполняет код, а не модель — иначе гарантия зависела бы
от того самого компонента, который может ошибиться.

**Третий: порог релевантности.** Если ни один фрагмент не набрал минимальной
оценки, генерация не запускается вовсе.

Результат: показать выдуманную статью система не может по построению. Это
блокирующий критерий приёмки из ТЗ.

## Правила отказа

Сервис обязан отказаться от содержательного ответа, если:

- ни один найденный фрагмент не преодолел порог релевантности;
- модель сообщила о низкой уверенности;
- обнаружена цитата, отсутствующая в контексте;
- в ответе нет обязательных полей.

Отказ выглядит как честное «я не нашёл точной нормы» плюс контакты живых
юристов. Отвечать по общим знаниям модели запрещено.

## Safety-режим для незадокументированных

Правило безопасности №1 из ТЗ: при `UNDOCUMENTED` нельзя первым шагом
рекомендовать обращение в полицию или на портал обращений без предупреждения о
последствиях.

Как исполняется:

1. Системный промпт требует ставить первым шагом НПО или консульство и
   объяснить риск проверки статуса.
2. Если модель предупреждение не вернула, его подставляет код — и в боте, и в
   API.
3. Неизвестный профиль (`UNKNOWN`) трактуется как незадокументированный.
   Консервативная трактовка закреплена в одном месте — свойстве
   `effective_risk` модели профиля, а не в разрозненных проверках.

Смысл: человек без документов, обратившись в госорган, может пострадать сам.
Формально верный совет здесь способен навредить.

## Признаки принудительного труда

Требование FR-23 и раздел ТЗ о принудительном труде. Отслеживаются: изъятие
документа, удостоверяющего личность; запрет покидать территорию; долговая
кабала; работа без оплаты под угрозой; удержания «за жильё и еду» сверх
зарплаты.

Реакция — приоритетное сообщение **до** основного ответа с телефоном
**116 16** (национальная горячая линия по борьбе с торговлей людьми,
круглосуточно, бесплатно, анонимно) и предложением обратиться в профильное НПО.

Детектор двухступенчатый: регулярные выражения плюс LLM-классификатор.
Ключевые слова работают всегда, включая ситуацию полного отказа внешних
сервисов — человек в опасности получит телефон в любом случае.

## Приватность

### Что сохраняется

| Данные | Где | Зачем |
|---|---|---|
| Профиль (гражданство, статус) | SQLite `sessions` | не переспрашивать |
| SHA-256 хеш вопроса | SQLite `queries` | метрики без раскрытия содержания |
| Идентификаторы найденных норм | SQLite `queries` | отладка качества поиска |
| Уверенность, red-flag, отказ, задержка | SQLite `queries` | статистика качества |

### Что не сохраняется

- **Текст обращений** — только хеш. Восстановить вопрос по нему нельзя.
- **Персональные данные из заявления** — ФИО, работодатель, суммы живут в
  памяти сессии и стираются после генерации файла.
- **Паспортные данные** — не запрашиваются вовсе (SEC-02).

### Права пользователя

Команда `/delete` удаляет и профиль, и служебные записи (SEC-04). Команда
`/reset` очищает профиль, не трогая статистику.

### Честность о границах анонимности

При первом запуске сообщается, что переписка в мессенджере не даёт абсолютной
анонимности (SEC-03). Для аудитории, которая может опасаться преследования, это
предупреждение существеннее любых заверений о конфиденциальности.

## Соответствие законодательству

| Требование | Реализация |
|---|---|
| SEC-01: уведомление об ИИ (Закон РК № 230-VIII) | в дисклеймере при `/start` и в подвале сайта |
| SEC-02: минимизация персональных данных | паспортные данные не собираются, заявление не сохраняется |
| SEC-03: предупреждение о неанонимности | сообщение при первом запуске |
| SEC-04: удаление данных | команда `/delete` |
| SEC-05: ключи только в переменных окружения | `.env` в `.gitignore`, в репозитории только `.env.example` |

## Границы предметной области

Сервис отвечает только по трудовым отношениям и трудовой миграции. Семейное,
уголовное, налоговое, жилищное право — вне области, там ожидается отказ с
контактами помощи.

Это ограничение осознанное: качество достигается глубиной одной области, а не
широтой охвата. Расширение доменов вынесено в дорожную карту.

## Работа с ключами

- Ключи хранятся только в `.env`, который исключён из репозитория.
- В коде нет значений по умолчанию для секретов.
- При отправке проекта в GitHub содержимое `.env` проверяется отдельно.
- Если ключ попал в историю коммитов, его нужно **отозвать**, а не просто
  удалить файл: история остаётся доступной.
