# Оценка качества

## Тестовый датасет

Файл: [eval/dataset.json](../eval/dataset.json). Сорок вопросов в пропорции,
заданной ТЗ:

| Категория | Вопросов | Что проверяет |
|---|---|---|
| `in_domain` | 25 | содержательные ответы по трудовым правам |
| `borderline` | 8 | пограничные темы: налоги, аренда, выдворение |
| `out_of_domain` | 7 | отказ там, где отвечать нельзя |

Дополнительно размечены 5 вопросов с признаками принуждения и 7, где ожидается
отказ.

Формат записи:

```json
{
  "id": "q_001",
  "question": "Мне не платят зарплату 3 месяца, паспорт забрал работодатель",
  "profile": {"citizenship": "NON_EAEU", "risk": "UNDOCUMENTED"},
  "ground_truth": "Эталонный ответ для сравнения",
  "expected_articles": ["113"],
  "expects_red_flag": true,
  "expects_abstention": false,
  "category": "in_domain"
}
```

Поле `expected_articles` заполнено только там, где статья подтверждена
корпусом. Пограничные вопросы намеренно допускают как частичный ответ, так и
отказ — обе стратегии приемлемы, недопустима лишь уверенная выдумка.

## Запуск

```bash
python -m eval.run_eval            # собственные метрики
python -m eval.run_eval --ragas    # дополнительно RAGAS
```

Результаты по каждому вопросу сохраняются в `eval/results.json` — там видно,
какие нормы были найдены и что ответила модель.

Прогон делает 40 живых запросов к OpenAI. Учитывайте расход бюджета.

## Метрики

### Считаются без внешних библиотек

| Метрика | Цель | Смысл |
|---|---|---|
| Citation Accuracy | **1.00** | доля ответов без неподтверждённых статей |
| Abstention Rate | ≥ 0.90 | доля отказов среди вопросов вне области |
| Red-flag Recall | высокая | доля распознанных признаков принуждения |
| Latency p95 | ≤ 12 000 мс | время ответа (NFR-01) |

**Citation Accuracy — блокирующий критерий.** Значение ниже единицы означает,
что в ответ прошла статья, отсутствующая в найденном тексте закона. Это отказ
приёмки, а не повод для доработки промпта: при исправной работе валидатора
такой ответ не должен существовать в принципе.

### RAGAS

| Метрика | Порог | Смысл |
|---|---|---|
| Faithfulness | ≥ 0.85 | доля утверждений, подтверждённых контекстом |
| Context Precision | ≥ 0.70 | качество отбора фрагментов |
| Context Recall | ≥ 0.75 | полнота извлечения |
| Answer Relevancy | ≥ 0.80 | соответствие ответа вопросу |

Faithfulness — главная содержательная метрика: она показывает, насколько ответ
опирается на найденный закон, а не на общие представления модели.

## Ручные сценарии приёмки

Помимо метрик, ТЗ требует проверить пять сценариев вживую. Они проверялись
через API и подтверждены:

| Сценарий | Результат проверки |
|---|---|
| Red-flag на изъятии паспорта | сработал, распознаны «изъятие документов» и «неоплачиваемый труд под угрозой» |
| Ответ со ссылкой на статью | ст. 113 ТК РК (0.94), ст. 87 КоАП РК (0.94) |
| Развилка ЕАЭС | Кыргызстан — «разрешение не требуется» (ст. 97 Договора о ЕАЭС, 0.98); Узбекистан — «требуется» (Закон о миграции ст. 37, ТК РК ст. 26) |
| Отказ вне области | вопрос о погоде — отказ, все оценки 0.0 |
| Генерация документа | файл `.docx` формируется, 37 КБ |

Развилка ЕАЭС — самый показательный сценарий для демонстрации: один и тот же
вопрос даёт принципиально разные ответы в зависимости от гражданства, что
невозможно подделать общими знаниями модели.

## Автоматические тесты

```bash
python tests/test_smoke.py    # 7 проверок, без сети и тяжёлых моделей
python tests/test_api.py      # 17 проверок против живого API
```

`test_smoke.py` покрывает парсер (включая отсев утративших силу статей),
валидатор цитат на заведомо ложной ссылке, детектор red-flag на положительных и
отрицательных примерах, генерацию `.docx`, работу с базой (в том числе
отсутствие сырого текста в хранилище) и консервативную трактовку неизвестного
профиля.

`test_api.py` проверяет весь путь: отдачу лендинга и статики, срабатывание
red-flag, подтверждение цитат источниками, различие ответов по развилке ЕАЭС,
отказ вне области, отклонение некорректного ввода, скачивание документа.

## Наблюдение за качеством в работе

Таблица `queries` в SQLite накапливает обезличенную статистику: уверенность,
признаки red-flag и отказа, задержку, идентификаторы найденных норм. По ней
можно оценить, не слишком ли часто сервис отказывается и какие статьи
востребованы, не раскрывая содержание обращений.

```sql
SELECT
  COUNT(*) AS всего,
  SUM(abstained) AS отказов,
  SUM(red_flag) AS red_flag,
  ROUND(AVG(latency_ms)) AS средняя_задержка
FROM queries;
```

## Что делать при низких показателях

ТЗ фиксирует стоп-правило: при недостаточной достоверности **не расширять
корпус**, а сужать контекст и усиливать переоценку.

| Проблема | Действие |
|---|---|
| Faithfulness ниже порога | уменьшить `RERANK_TOP_K`, ужесточить промпт |
| Слишком много отказов | понизить `RELEVANCE_THRESHOLD` |
| Отвечает по слабо связанным нормам | повысить порог |
| Нужная статья не доходит до модели | увеличить `RETRIEVAL_TOP_K` |
| Citation Accuracy ниже 1.00 | искать ошибку в валидаторе — это дефект, а не настройка |

Добавление документов в корпус увеличивает шум при поиске и обычно ухудшает
достоверность, а не улучшает её.
