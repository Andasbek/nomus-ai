# Telegram-бот

Бот на aiogram 3, точка входа — [nomus/bot/main.py](../nomus/bot/main.py),
запуск: `python -m nomus.bot.main`.

## Команды

| Команда | Действие |
|---|---|
| `/start` | дисклеймер и сбор профиля; при повторном входе — сразу к вопросам |
| `/reset` | очистить профиль и начать заново (FR-05) |
| `/delete` | удалить все данные пользователя (SEC-04) |
| `/help` | краткая справка |

## Сбор профиля

Требования FR-01 — FR-04. Диалог состоит из четырёх шагов и проходится один раз.

```
/start
  │
  ▼
Дисклеймер + уведомление об ИИ + предупреждение о неанонимности
  │  кнопка «Понятно»
  ▼
Гражданство:  Узбекистан / Кыргызстан / Таджикистан / Другое
  │           Кыргызстан → EAEU, остальные → NON_EAEU
  ▼
Есть письменный трудовой договор?      Да / Нет / Не знаю
  │
  ▼
Есть действующая регистрация?          Да / Нет / Не знаю
  │
  ▼
Готов к приёму вопросов
```

Профиль риска выводится из двух ответов:

| Договор | Регистрация | Профиль |
|---|---|---|
| да | да | `DOCUMENTED` |
| любой ответ «нет» | | `UNDOCUMENTED` |
| остальные сочетания | | `UNKNOWN` → трактуется как `UNDOCUMENTED` |

Профиль сохраняется в SQLite и не запрашивается повторно (FR-04). Если человек
уже проходил опрос, `/start` сразу приглашает описать ситуацию.

Дисклеймер обязателен до начала работы: он сообщает, что собеседник — ИИ
(требование SEC-01 по Закону РК «Об искусственном интеллекте») и что сервис не
заменяет юриста.

## Ответ на вопрос

Обработчик в [handlers.py](../nomus/bot/handlers.py) принимает любой текст, не
начинающийся со слэша, обрезает до 1000 символов и передаёт в оркестратор
вместе с профилем.

Порядок сообщений важен:

1. **Красное предупреждение red-flag**, если сработал детектор — отправляется
   первым, до основного ответа (FR-23). Человеку в опасности телефон 116 16
   нужен раньше правовой справки.
2. **Основной ответ**: суть → права со ссылками на статьи → предупреждение о
   рисках → план действий → контакты → дисклеймер (FR-14).
3. **Кнопки**: «Сформировать заявление» (только если пайплайн его предложил) и
   «Нужен живой юрист».

При отказе выдаётся честное объяснение и кнопка вызова контактов помощи. При
сбое — сообщение об ошибке с телефонами 1414 и 116 16.

### Страховка для незадокументированных

Требование FR-24 обязывает добавлять предупреждение о рисках при
`UNDOCUMENTED`. Обычно его формирует модель, но если она этого не сделала,
[render.py](../nomus/bot/render.py) подставляет предупреждение сам, вместе со
списком безопасных первых контактов: НПО, консульство, анонимная горячая линия.

Полагаться здесь только на модель нельзя — цена пропуска слишком высока.

## Генерация заявления

Требования FR-30 — FR-33. Кнопка появляется, когда пайплайн распознал ситуацию
невыплаты зарплаты.

Бот последовательно спрашивает шесть полей: ФИО, гражданство, работодатель,
период работы, сумма долга, контакт. Затем формирует `.docx` и отправляет
файлом. В заявление подставляются статьи из предыдущего ответа — те, что
подтверждены поиском.

**Персональные данные живут только в памяти конечного автомата** и стираются
сразу после отправки файла. В базу они не попадают.

Если генерация файла не удалась, бот отправляет текст заявления сообщением —
запасной вариант, предусмотренный ТЗ.

## Прогрев моделей

При старте бот прогружает модели поиска и переоценки до начала опроса Telegram.
Без этого первый пользователь ждал бы около 40 секунд, что нарушает требование
по времени ответа (NFR-01) и создаёт плохое первое впечатление на демонстрации
(NFR-04).

Если прогрев не удался, бот всё равно поднимается: пайплайн вернёт ошибку с
контактами помощи, а не оставит сервис лежащим.

## Хранение данных

| Таблица | Содержимое |
|---|---|
| `sessions` | профиль, язык, факт принятия дисклеймера |
| `queries` | SHA-256 хеш вопроса, найденные фрагменты, уверенность, признаки red-flag и отказа, задержка |

Текст обращений не сохраняется. Хеша достаточно для подсчёта повторов и метрик,
но по нему нельзя восстановить, о чём спрашивал человек. Команда `/delete`
удаляет записи из обеих таблиц.

Состояние конечного автомата хранится в памяти процесса (`MemoryStorage`) —
после перезапуска бота незавершённый сбор полей заявления придётся начать
заново, но профиль сохранится, поскольку лежит в базе.

## Структура модулей

| Файл | Назначение |
|---|---|
| `main.py` | запуск, прогрев, подключение обработчиков |
| `handlers.py` | команды, шаги профилирования, приём вопросов, заявление |
| `states.py` | состояния конечного автомата |
| `keyboards.py` | inline-клавиатуры |
| `render.py` | сборка текста сообщений, дисклеймеры, страховки |

Логики ответа в боте нет — он вызывает `process_query()` и отрисовывает
результат.

## Проверка сценариев вручную

| Сценарий | Что ввести | Ожидаемо |
|---|---|---|
| Red-flag | «не платят 3 месяца, паспорт забрал работодатель» | красное предупреждение с 116 16 перед ответом |
| Развилка ЕАЭС | «нужно ли мне разрешение на работу» при гражданстве Кыргызстана и Узбекистана | принципиально разные ответы |
| Отказ | «какая погода завтра в Алматы» | честный отказ и контакты |
| Документ | «не платят зарплату», профиль с документами | кнопка заявления, затем файл `.docx` |
| Безопасный режим | тот же вопрос без документов | первым шагом НПО или консульство |
